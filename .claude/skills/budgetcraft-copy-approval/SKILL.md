All customer-facing copy in this project follows a Draft → Approved → Published lifecycle, and
only the operator (never Claude) advances a piece of copy out of Draft.

Rules:
1. Any new or edited copy you write is Status: Draft by default. Never write "Approved" or
   "Published" into a checklist or file yourself.
2. When drafting emails, record for each one: Subject, Preview text, Goal, Primary CTA,
   Expected reader action, Links used, a brand-voice checklist, and Status — mirroring the
   format in docs/email-review-checklist.md.
3. Apply 04_BRAND_VOICE.md's four decision filters to every line: would Sarah understand this
   without looking anything up; does it blame the tool rather than her; is the promise right
   for this funnel stage; is warmth coming from specificity rather than punctuation.
4. Never use language from 00_LOCKED_DECISIONS.md §15's banned list (founder-voice claims like
   "we've all been there," exclamation-driven over-reassurance, shame register, false-veteran
   claims, or anything resembling financial advice).
5. Never send a test email, activate a Kit automation, or push copy to a live page as part of
   "finishing" a task. Drafting and reviewable-checklist creation is the deliverable; shipping
   is a separate, operator-only step.
